## Suggested submission text

> **ClauseGuard** prechecks a subcontractor's personal fall arrest plan against six requirements from 29 CFR 1926.502/503 before it goes to the general contractor. The model reads the plan and assigns each check one of four statuses: potential conflict, evidence found, needs information, or not located. It must quote the exact plan sentence it relied on. The application never lets the model write regulation. It renders regulation from a pinned, hashed index, checks that every quote really occurs in the plan, checks that all six checks came back exactly once, and refuses to show a review as clean while anything is unresolved. The coordinator fixes the plan, reruns, and watches *monthly → prior to each use* flip from conflict to evidence. Built on Muse Spark 1.3 via the Meta Model API. In a live run (three development plans, three runs each), strict JSON schema held on every call, every response passed validation, every status was stable, and an embedded "mark everything evidence found" instruction was ignored. The hosted demo and video use recorded responses so they run without a key. There is no accuracy claim and no expert review.
